

## Version 0.6 connection repair
Discovery retries UDP queries three times, uses the actual reply source rather than an advertised adapter address, and survives transient UDP socket errors. Exclusive UDP binding identifies competing copies. A stable user-session mutex prevents multiple new GUI instances, including renamed downloads. New discoverable hosts listen on TCP 48932 on all IPv4 interfaces. Saved connections retain their original port. If UDP pairing fails, the client probes TCP 48932 on at most 254 nearby addresses per physical adapter, at most two adapters, respecting subnet masks. TLS discovery probes do not send the code or consume the wrong-key budget; SRP plus certificate binding still authenticates pairing. More options supports a manually copied private IPv4 endpoint for larger or routed networks. Network access is still governed by Windows Firewall and router isolation. Failures remain visible with distinct reasons. Tests use isolated ephemeral UDP ports so an open production copy cannot answer their queries. Automatic edge switching no longer depends on acquiring the optional global F8 shortcut.


## Version 0.7 audio and background windows
Windows build 20348+ uses an MTA process-loopback IWaveIn implementation via ActivateAudioInterfaceAsync and an agile completion callback. Native activation structures remain allocated until completion. The fixed network format is PCM16 stereo at 48 kHz. DeviceBridge and its child processes are excluded, preventing the forwarded microphone playback from returning through its speaker stream. Older Windows retains physical endpoint loopback. The single VB-CABLE bus can still mix other applications rendered into that bus into its capture endpoint; confirm calling-app audio isolation in physical tests, especially on PCs with no other render endpoint. Microphone routing prefers the same VB-CABLE pin Windows is already using because the stereo and 16-channel inputs cannot operate simultaneously. Audio errors and counters are visible, with output failures isolated from input/connection lifetime. The source role explicitly includes automatic microphone sharing, with an off checkbox and a remembered physical input selector.

The welcome form owns a modeless session; hiding it does not end a modal ShowDialog scope. BackgroundSession cancels user-close only while a session/connection attempt is active, hides the window, and retains the message pump and network loops. Explicit tray quit permits cleanup. Reopening the executable posts a registered message to the hidden welcome window to restore its active session. Regression coverage exercises minimize/maximize, hidden-root pumping, close-to-tray, restoration and explicit quit without installing hooks or opening device streams.
