TRUSTED APP SIGNING REMAINS PENDING
The app executable is still unsigned. No signing certificate was present, and the
user chose to prepare signing for later. Sign-Release.ps1 supports an existing
trusted code-signing certificate in the Windows certificate store, never a pasted
private key. A Microsoft Artifact Signing account may instead be integrated through
its official signing tooling once identity verification and access are ready.

Release order: build -> hardware validation -> sign executable -> verify Authenticode
and timestamp -> regenerate website release.json and download parts -> publish.
Signing changes the binary hash. Never re-use old release hashes after signing.
The script does not disable Windows warnings or security protections. Valid signing
identifies a publisher; Microsoft SmartScreen reputation is a separate decision and
may still show warnings on new files. A Store distribution route can be evaluated.
https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation
